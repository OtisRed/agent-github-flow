# Repository CI

`Repository CI / verify` runs for pull requests targeting `main` or `smoke`, including drafts, and pushes to those branches. It checks the pull request merge result using a read-only GitHub token with checkout credentials disabled. It runs the Node tests, validates all GitHub Actions workflows using a versioned, checksum-verified actionlint binary, and checks that actionlint rejects a deliberately invalid fixture. The actionlint run does not invoke ShellCheck; the check is workflow validation, not a comprehensive shell audit.

This workflow does not reference App keys, PATs, or protected environments. Fork pull requests run without repository secrets. To preserve that boundary for changes originating in this repository, do not store project credentials as repository-wide Actions secrets; use protected environments and trusted code. A pull request can change its own tests and workflow, so a passing check does not replace independent review of those changes.

This CI is bootstrapping itself. Before requiring its check in branch protection, verify the check name and successful current-merge-SHA runs on pull requests to both `smoke` and `main`, and separately verify the future promotion path. A workflow missing on a base branch, a renamed check, a pull-request merge conflict, or blocked fork approval may prevent the required status from appearing. Inspect the Actions run, current PR and merge SHA, environment and branch rules; rerun only the appropriate current run or correct the workflow through a reviewed PR. An absent check is not a passing result. If recovery is impossible, an administrator can adjust branch protection and record why; do not silently bypass review.

The actionlint version and SHA-256 must be updated together after verifying the release. A checksum failure or unreachable download fails the check. CI validates repository changes; it does not test Project writes, private-key rotation, nightly reconciliation, or owner smoke.
