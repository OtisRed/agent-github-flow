# Odczytowe połączenie kolejki z kontrolerem

Issue #79 przygotowuje ograniczone połączenie weryfikacyjne, nie uruchomiony worker. `read_delivery` odczytuje jeden wskazany identyfikator dostawy z bazy #77 po sprawdzeniu właściciela, schematu i klucza. Nie usuwa wpisu, nie rezerwuje go i nie oznacza jako wykonanego. Identyfikatory liczbowe przekazuje jako kanoniczne ciągi cyfr, bez strat przy przejściu z Pythona do JavaScript.

`observeIngressDelivery` wybiera parę instalacja/repozytorium w dostarczonym rejestrze i przekazuje numer issue oraz rejestrację do wstrzykniętego resolvera. Rejestr i jego powiązanie z ID instalacji/repozytorium muszą być dostarczone przez niezależnie zaufane, chronione źródło; sam adapter nie zapewnia tego zaufania. Dotychczasowy `resolveV3ProjectPolicy` weryfikuje HMAC pełnej rejestracji i dwukrotnie odczytuje tożsamość issue. W rzeczywistej instalacji transport i klucze wymagają osobnego, bezpiecznego złożenia i ograniczenia zakresu. Wynik `observed` oznacza tylko rozpoznanie polityki, nie ukończenie pracy, odczyt całego kontraktu, zgodę na zmianę statusu ani dowód braku replay.

Na Mikrusie Node 22.23.4 uruchomiony w prywatnym katalogu tymczasowym przeszedł 533 syntetyczne testy draftu kontrolera. Dodatkowa próba połączyła dwie sztuczne dostawy w kolejce z rzeczywistym resolverem v3 z draftu `395c3b296172fce536f7ce1c2faae3e177140fbd`, z fikcyjnym transportem, kluczem i rejestracjami. CI pobiera ten dokładny commit jako fixture do tej próby. Nie jest to zainstalowany lub utrzymywany runtime ani test rzeczywistej komunikacji GitHub.

Bezpieczne uruchomienie nadal wymaga trwałego stanu pracy i odzyskiwania, ograniczenia replay, sterowania jedną kolejką, zaufanej rejestracji i poświadczeń oraz obsługi błędów, niedostępności i eventów lifecycle. Obecne `closed`, `reopened`, `deleted` i `transferred` są jawnie blokowane. Nie jest tu zaimplementowana obserwacja pełnego checkpointu, rzeczywisty HTTP, worker ani mutacja statusów. Ochronę ścieżki SQLite i konsekwencje ewentualnego hot journal opisuje `webhook-ingress.md`.
